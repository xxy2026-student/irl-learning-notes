## 怎么确认自己写对了

**写测试，而且优先写“不需要知道正确答案也能检查”的那种。**
这类守恒律 / 一致性检查最有价值，因为它们不依赖你对答案的猜测：

- 概率分布必须和为 1（转移矩阵的每一列、policy 的每一列）
- 用**两条独立的路径**算同一个量，结果必须相同
- 总量守恒：某些量的总和有解析上的必然值，对不上就是有 bug

自己想得出第二条和第三条的具体形式，就代表真的懂那个算法在算什么。

另外：**IRL 的内循环是一次 forward RL。**
阶段 0 的代码有 bug 的话，阶段 2 的梯度整个是错的，
而且**看起来还是会收敛**——所以阶段 0 的测试不要省。

## 评估反推结果的时候

比较“反推的 reward”和“真实 reward”之前，先想清楚一件事：
**reward 本来就不是唯一的**（阶段 1 和阶段 4 的主题）。
所以直接比数值大概会得到很难解读的结果。

先想好要用什么指标、为什么那个指标公平，再开始跑实验。
指标选错的话，数字会和直觉对不上，而那时候**要先怀疑指标**。
